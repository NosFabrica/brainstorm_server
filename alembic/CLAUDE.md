# alembic

Database migrations for PostgreSQL. Standard Alembic layout.

## Files

- `env.py` — wires Alembic into the app:
  - Loads `settings` from `app/core/config.py` to pick up `database_url`.
  - Imports `Base` from `app/db_models/__init__.py` for autogenerate to compare against.
  - Runs migrations through SQLAlchemy's **sync** engine (Alembic doesn't support async out of the box).
- `script.py.mako` — boilerplate template.
- `README` — alembic's stock README.
- `versions/` — one file per migration. 17 files at the time of writing; see history below.

## Running migrations

```bash
# Apply all pending migrations
alembic upgrade head

# Roll back one revision
alembic downgrade -1

# Generate a migration from model diffs
alembic revision --autogenerate -m "add foo column"
```

In the deployment compose stack, migrations are applied automatically by a
sidecar before the server starts. Locally, run them by hand.

## Conventions

- **Always review autogenerated migrations.** Alembic's diff doesn't catch:
  - Constraint name changes
  - CHECK constraints
  - Server defaults on existing columns
  - Index name renames vs drop+create
  - Type changes that need a USING clause on Postgres
- Set `server_default` on every NOT NULL column you add to an existing table. Otherwise the migration fails on rows that pre-existed.
- Custom data backfills go inline in the migration (`op.execute("UPDATE ... ")`) — keep them idempotent so re-running doesn't double-apply.
- Filenames are `<hash>_<slug>.py`. Don't rename them after they've shipped — the hash is the migration's identity.

## env.py snags

- The async / sync split: `database_url` in `app/core/config.py` is the asyncpg URL the app uses. Alembic needs the sync `psycopg2` URL. `env.py` rewrites the scheme. Don't add `+asyncpg` in `database_url` unless you also update `env.py`.
- Autogenerate uses `target_metadata = Base.metadata`. That means every model file in `app/db_models/` must be imported (transitively) by `env.py` — adding a new model file without importing it makes autogenerate think tables don't exist and drop them.
