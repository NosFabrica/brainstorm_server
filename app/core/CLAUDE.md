# app/core

Shared, dependency-free infrastructure modules. Everything else imports from here.

## Modules

| File | Purpose |
|---|---|
| [`config.py`](config.py) | Pydantic `Settings`. All env vars are declared here; unknown keys are ignored (`extra="ignore"`) so a `.env` still setting a removed var boots. `settings = Settings()` is the singleton other modules import. To add a setting: add the `Field(...)` here AND mirror in `../../env.example` AND any compose file that runs this service. |
| [`loggr.py`](loggr.py) | Logging setup. Always do `from app.core.loggr import loggr; logger = loggr.get_logger(__name__)`. Don't use `print` or stdlib `logging.getLogger` directly. |
| [`search_relay.py`](search_relay.py) | Forwards ORE-05 to the shared search relay's `POST /search/pubkeys`; raises `SearchRelayUnavailable` when the relay is unreachable or answers outside the ORE-05 shape. Lazy shared `_client`, `aclose()` in the lifespan. |
| `admin_whitelist.py` / `billing_admin_whitelist.py` | Who may reach `/admin/*` and `/admin/billing/*` respectively. Separate lists on purpose — billing views carry payment data, and whoever answers payment questions should not inherit nsec key rotation. Billing falls back to the admin list when unset, so an existing deployment keeps working; once configured it is authoritative. Both parse via `admin_whitelist.parse_pubkey_list`. |
| [`flash.py`](flash.py) | Flash subscription reads (payments). Same shared-client shape as `search_relay.py` — lazy module-level `_client`, `aclose()` in the lifespan. An unreadable Flash must raise, because returning "no subscription" for a socket timeout would revoke someone who is paying. `FlashUnavailable` is transient and retried; `FlashCredentialError` is not. A 404 is absence on the path lookup (`/subscriptions/{id}`) and a failure on the filtered list (`?ref=`). That path read is also the checkout-return verification: Flash offers `/{id}/verify` as an equivalent, and we make the call **one way, not two** — the only difference is a 200 with `valid: false` where the path 404s, and both collapse to the same `None` here, while `fetch_subscription_raw` needs the path read anyway. Also holds the plan read (`GET /services/{id}`), where a 404 is neither: it raises `FlashServiceMissing`, because our own configuration names a service Flash does not have. The two **writes** (`cancel_subscription`, `set_subscription_status`) share that interpretation via `_body_of`, but retry differently: only a failure to *connect* is repeated, because a read that times out can be asked again for free while a cancellation that times out may already have been applied. A 5xx is not retried either — Flash answering means Flash received it. Writes need the `subscriptions:manage` scope reads do not, so a key without it fails as `FlashCredentialError`, not as an outage. A write's other 4xx raises `FlashRefused` — Flash was reached and declined, which an operator can act on, unlike a read's 4xx (our URL is wrong and there is nothing to act on). |
| [`flash_plan_cache.py`](flash_plan_cache.py) | Flash's plans, cached in Redis, because `/billing/plans` is public and unauthenticated. Two entries per service: a short-lived copy that keeps anonymous traffic off Flash's quota, and a **last-known-good copy with no expiry** served whenever Flash cannot be read — a TTL on that one would let an outage empty the pricing page, which is what it exists to prevent. `read_service_plans(fresh=True)` is the operator's read: it skips the short-lived copy, asks Flash now and rewrites both entries, so an admin looking at a plan catches the public page up. Only "we could not ask" falls back. `read_plans_for_services` catches both `FlashUnavailable` (nothing cached) and `FlashServiceMissing` per service, logs, and omits that service's plans, so one bad id degrades `/billing/plans` rather than refusing it. |
| `database.py` | Async PostgreSQL `db_session()` context manager (asyncpg via SQLAlchemy). |
| `redis_db.py` | `redis_client` async singleton + queue helpers. |
| `sql_admin_panel.py` | SQLAdmin integration mounted by `app.api`. |
| `tier_thresholds.py` | The fixed tier bands + `classify_tier`. The read endpoints bucket subjects in Cypher (`user_repo._TIER_PREDICATES`); the GrapeRank result writer buckets in-memory scorecards it hasn't written to the graph yet, so it can't run that query and needs this second implementation. `tests/integration/test_tier_classifier_matches_cypher.py` asserts the two agree. `DEFAULT_VERIFIED_THRESHOLD` is a fallback only — the live verified line comes from the observer's saved preset. |
